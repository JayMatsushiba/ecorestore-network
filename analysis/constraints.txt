# Resolved dependency set of the analysis image — every package, pinned.
#
# WHY THIS FILE EXISTS
#
# Bit-exact parity with the TypeScript engine is the acceptance test for this
# implementation (`docs/DEVELOPMENT_LOG.md`, decision 1), and floating-point
# results depend on the NumPy and SciPy builds that produce them. `pyproject.toml`
# declares open-ended minimums, which is right for a library and wrong for an
# image whose numbers are committed to a hash: two rebuilds a month apart would
# resolve different versions and could return different numbers under the same
# `analysisEngine` identity. This file is what `Dockerfile` installs against, so
# a rebuild reproduces the stack the parity suite was run on.
#
# TO CHANGE IT
#
#   1. edit the pin,
#   2. rebuild and run the parity suite *inside the image* — every number must
#      still be equal, not close,
#   3. bump `ENGINE["version"]` in `ecorestore_analysis/__init__.py`, because the
#      result hash commits to the engine identity and the numeric stack is part
#      of what that identity is standing for,
#   4. regenerate the committed assurance bundles.
#
